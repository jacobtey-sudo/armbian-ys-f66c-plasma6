# Релизы

## Что считается артефактом

Сборка создаёт в `output/images/`:

- `*.img` — образ для microSD/eMMC;
- `*.img.sha` — SHA256;
- `*.img.txt` — отчёт: версии, пакеты, checksums, параметры сборки.

Образ весит около 9 ГБ и **не коммитится** и не публикуется в git.
Репозиторий хранит только исходники, конфиги, пины и checksums.

## Версионирование

Версия образа — из Armbian (`26.11.0-trunk` и т. п.) плюс имя платы, релиз,
ядро и рабочий стол:

```text
Armbian-unofficial_<armbian>_Ys-f66c_trixie_vendor_<kernel>_kde-plasma_desktop.img
```

Релизный тег репозитория — `v<major>.<minor>.<patch>`; в release notes
указываются:

- коммиты `ARMBIAN_BUILD_COMMIT` и `ARMBIAN_BASE_COMMIT`;
- версии Plasma, Qt и ядра;
- checksum образа;
- изменения и известные проблемы.

## Чек-лист релиза

1. Обновить пины в `config/versions.env` отдельным коммитом.
2. Собрать образ из чистого рабочего дерева:

   ```sh
   rm -rf build
   ./scripts/build.sh
   ```

3. Проверить checksum:

   ```sh
   sha256sum -c build/output/images/*.img.sha
   ```

4. Записать образ на microSD и пройти smoke-тест:
   - загрузка и поворот на всех этапах;
   - SDDM и вход;
   - панель, апплеты, окно;
   - Maliit (ru/en, размеры);
   - звук: динамик, наушники, микрофон;
   - Bluetooth A2DP + HFP, автоподключение;
   - Wi-Fi/Ethernet;
   - камера `/dev/video10`;
   - кнопка питания и `shutdown`;
   - `systemctl --failed` пуст.
5. Проверить, что в образе нет пользовательских данных, ключей и реальных
   MAC.
6. Записать checksum и отчёт в release notes.
7. Поставить тег и опубликовать release notes.

## Публикация образа

Образ не входит в git. Готовые образы публикуются в GitHub Releases:
`.img.xz`, рядом `.img.xz.sha256` и `.img.txt`. Лимит GitHub — 2 ГиБ на
файл, поэтому архив сжимается `xz -T0 -6`; на `-1` выходит 2,23 ГиБ и не
влезает.

В репозитории остаются тег, release notes и checksums.

Перед публикацией убедиться, что в образе нет:

- SSH-ключей, паролей, токенов;
- MAC-адресов и серийных номеров;
- домашних каталогов конкретных пользователей;
- логов с адресами и учётными данными.

## Откат

Предыдущий образ и его checksum хранятся отдельно от рабочего дерева.
При проблемах вернуться на предыдущий тег, пересобрать из его пинов и
сравнить `*.img.txt`.
